# PLAN — CLE5 개발 계획

## 실행 계획

### Phase 1: 요구사항 기준선과 자료 정리
- **담당**: Codex
- **입력**: Issue #51, CLE4 요구사항, 제공된 성장 루프 6개 파일
- **출력**: CLE2-19 표준 문서, 출처 보존 research 자료, CLE4/CLE5 경계
- **예상 시간**: 0.5일

### Phase 2: CLE5 실행 계약과 데이터 모델
- **담당**: Codex
- **입력**: Phase 1 산출물
- **출력**: 저장소 구조, tag/case/assessment/principle/changelog schema, 상태 전이 규칙
- **예상 시간**: 1일

### Phase 3: Growth Loop 실행기와 검증기
- **담당**: Codex
- **입력**: 데이터 모델과 G1~G5 계약
- **출력**: 초기화, 태깅, 승격/은퇴 판정, 부팅 컨텍스트 조립, 무결성 검사 명령
- **예상 시간**: 2일

### Phase 4: 작가/비평가 분리 및 시범 운영
- **담당**: Codex + 회장님
- **입력**: CASE-0001, 선택된 에피소드 산출물
- **출력**: 독립 비평 결과, 자기평가, 사람 피드백 간극, 한 번의 완결된 성장 루프
- **예상 시간**: 1~2일

### Phase 5: 측정, 개정과 확장 결정
- **담당**: Codex + 회장님
- **입력**: 시범 운영 기록
- **출력**: 반복 실패율/재작업/간극/체크리스트 지표, SYSTEM 개정안, 다음 에피소드 적용 결정
- **예상 시간**: 1일

## 의존성
- CLE2-9의 CLE4 설계와 원본 철학/blueprint 자료
- CLE2-13의 Unknown Discovery 및 사람 승인 원칙
- 첫 시범 에피소드의 원본, 수정본과 피드백
- 장기 운영 시 비평가 호출 비용 및 모델 접근

## 도구 및 접근
| 도구/데이터 | 목적 | 접근 상태 | 대안 |
|---|---|---|---|
| GitHub Issue/PR | 요구사항과 변경 이력 | available | 없음 |
| Markdown/YAML/JSON | 사람이 읽고 기계가 검증하는 원본 | available | 없음 |
| Node.js | schema와 상태 전이 검증 | available | 저장소 언어에 맞춰 변경 가능 |
| 작가/비평가 모델 호출 | 생성과 독립 검수 | undecided | 동일 모델을 분리된 새 호출로 운영 |

## 사람 승인 게이트
| 게이트 | 승인 대상 | 승인자 | 기준 |
|---|---|---|---|
| G0 시스템 경계 | 독립 CLE5 저장소 또는 CLE4 개정 | 회장님 | 소유 데이터와 배포 책임이 명확함 |
| G1 시범 시작 | 기준 에피소드와 입력 자료 | 회장님 | 원본/수정본/피드백 출처가 확인됨 |
| G2 원칙 승격 | WATCH → PROMOTED 문항 | 회장님 | 3개 사례와 판정 가능한 문구가 있음 |
| G3 확장 | 다음 에피소드 적용 | 회장님 | 재발률 감소와 체크리스트 비대화 방지가 확인됨 |

## 리스크
- CLE2-9에 CLE3와 CLE4가 함께 등록된 번호 충돌을 CLE5까지 확산하지 않는다.
- 단순 카운트만으로 원칙을 자동 승격하지 않고 근거 사례와 사람 승인을 요구한다.
- 비평가에게 작가 의도와 구조 문서를 제공하지 않아 결과물 중심 판정을 유지한다.
- 사례가 늘면 전체를 로드하지 않고 INDEX의 대표 사례와 현재 WATCH 항목만 부팅한다.
