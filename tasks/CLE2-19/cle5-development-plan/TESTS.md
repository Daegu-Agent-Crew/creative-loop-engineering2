# TESTS — CLE5 개발 계획

## 검증 기준

### 기능 테스트
| # | 테스트 항목 | 방법 | 기대 결과 | 통과 |
|---|------------|------|-----------|------|
| 1 | 요구사항 등록 | GitHub/CLE2 확인 | Issue #51과 CLE2-19 문서가 연결된다 | ☑ |
| 2 | 표준 문서 | 파일 검사 | GOAL/DISCOVERY/PLAN/STATUS/TESTS/DECISIONS가 존재한다 | ☑ |
| 3 | 입력 자료 보존 | 파일 및 diff 검사 | 제공된 6개 파일이 research 아래 출처 자료로 보존된다 | ☑ |
| 4 | CLE4/CLE5 경계 | 문서 리뷰 | 선행 철학과 신규 성장 책임이 구분된다 | ☐ |
| 5 | Growth Loop 상태 전이 | 자동 테스트 | G1~G5 및 ACTIVE/WATCH/PROMOTED/RETIRED 전이가 재현된다 | ☐ |
| 6 | 근거 무결성 | 자동 테스트 | tag count, CASE ID, 패널 인용과 원칙 변경 근거가 일치한다 | ☐ |
| 7 | 작가/비평가 분리 | 시범 실행 | 비평가는 작가 의도 없이 결과물과 사례만으로 판정한다 | ☐ |
| 8 | 세대 상속 | 새 세션 시범 | 부팅 후 WATCH 항목과 대표 사례를 정확히 요약한다 | ☐ |
| 9 | 한 주기 재현 | E2E | CASE-0001 기반으로 자기평가부터 시스템 개정까지 추적된다 | ☐ |
| 10 | 대시보드 조회 | 브라우저 확인 | CLE2-19 상세에서 6개 관리 영역과 자료 링크를 조회한다 | ☑ |

### 비기능 테스트
| # | 테스트 항목 | 방법 | 기대 결과 | 통과 |
|---|------------|------|-----------|------|
| 1 | 컨텍스트 예산 | 부팅 출력 측정 | 사례가 늘어도 대표 사례와 WATCH 중심으로 입력 크기가 제한된다 | ☐ |
| 2 | 비대화 방지 | 4개 에피소드 시뮬레이션 | 체크리스트가 10개를 넘으면 통합/은퇴 심사가 발생한다 | ☐ |
| 3 | 감사 가능성 | Git 기록 확인 | 모든 승격/은퇴가 사례, 결정, 승인과 커밋에 연결된다 | ☐ |

### 자동화 테스트 (해당 시)

node scripts/validate-growth-loop.js
node scripts/build-boot-context.js --project <project> --episode <episode>
