# DECISIONS — CLE3 수렴 루프 시스템 도입

## D-001: GOAL/STATUS 진행률 수치 재기준화
**결정일**: 2026-08-14
**배경**: state.json에 "17/49"으로 기재되었으나, `panels/assets/`에는 48개의 이미지 파일이 존재하고 `panels/final/`(오버레이 완료본)에는 17개가 있음.
**결정**: 진행률을 3단계로 분리하여 표기:
1. `generated`: 원본 패널 이미지 존재 (EP001 48/49, EP002 30/57)
2. `overlay_complete`: 대사 오버레이 완료 (EP001 17/49)
3. `qa_approved`: QA 통과 (미정)
**근거**: sfex11 코멘트 §1 "진행률을 분리해야 한다".

## D-002: 기존 파일은 "개편" 대상
**결정일**: 2026-08-14 (정정)
**배경**: 1차 조사에서 핵심 파일이 존재하지 않는 것으로 오인. 실제로는 `run-panel-jobs.js`(172라인), `evaluation-rubric.md`(v2), `IMAGE-WORKFLOW.md`, `AI-COLLABORATION-PROTOCOL.md` 모두 존재.
**결정**: 기존 파일을 기반으로 **개편**. 신규 작성이 아님. 단, 수렴 루프에 필요한 신규 파일(비교 스키마, preference-memory.json 등)은 추가 작성.
**정정**: 이전 버전 DISCOVERY의 "전부 미존재" 기록은 잘못된 리포 조사로 인한 오류.

## D-003: 구현 순서 — Evaluator를 루프보다 먼저
**결정일**: 2026-08-14
**배경**: 원안 PLAN은 Phase 2(마이크로 루프)를 Phase 3(Evaluator)보다 먼저 실행. 그러나 평가 기준 없이 루프를 돌면 수렴을 보장할 수 없음.
**결정**: 구현 순서 조정:
1. 비교·선택 데이터 스키마 설계
2. A/B/C Evaluator + 절대 품질 게이트 (both_bad/tie 포함)
3. Panel Runner 확장 (run-panel-jobs.js 개편)
4. 선호 메모리 & 레퍼런스 체인
5. 에피소드 회고 & 캘리브레이션
**근거**: sfex11 코멘트 §3 "구현 순서 수정".

## D-004: 절대 품질 게이트 유지
**결정일**: 2026-08-14
**배경**: A/B 비교평가만 사용하면 후보가 모두 불량일 때 "덜 나쁜 것"이 선택되어 preference memory를 오염시킬 수 있음. 기존 evaluation-rubric.md는 50점 만점에 40점 통과 기준이 이미 존재.
**결정**: A/B 비교와 병행하여 기존 절대 품질 게이트(40점)를 유지. `both_bad` → 전부 재생성, `tie` → 둘 다 유지하고 회귀 데이터로 활용.
**근거**: sfex11 코멘트 §3.

## D-005: Phase 4 / Phase 5 평가 범위 분리
**결정일**: 2026-08-14
**배경**: 현재 루브릭은 Phase 4에서 한글 렌더링을 평가하나, 생성 정책은 `final_text_in_image: false`(대사 후처리). 모순.
**결정**:
- Phase 4 평가: 캐릭터 일관성, 구도, 감정 연출, 화풍 일관성, 장면 연속성
- Phase 5 평가: 대사 오버레이 가독성, 맞춤법, 레이아웃, 최종 공개본 품질
**근거**: sfex11 코멘트 §6 "평가 규칙 정리".

## D-006: 후보 파일 관리 — Git 미커밋, 임시 영역
**결정일**: 2026-08-14
**배경**: 패널당 2~3후보 × 2~3회 반복. 모두 Git에 커밋하면 리포 비대.
**결정**: candidate/rejected 파일은 임시 작업 영역에 보관. 선택된 최종본만 `panels/assets/`로 승격. 체크포인트는 5~10개 단위.
**근거**: sfex11 코멘트 §5 "저장·비용 기준".

## D-007: 검증 전략 — 단일 패널 end-to-end 먼저
**결정일**: 2026-08-14
**배경**: 처음부터 전수 적용하면 비용만 소모하고 효과 검증이 어려움.
**결정**: 대표 패널 3개(단인물, 다인물, 풀페이지/고난도) 선정 → 후보 2× 최대 2회로 end-to-end 검증 → 사람 블라인드 선호 결과와 AI 판단 비교 → EP002로 확대.
**근거**: sfex11 코멘트 "권장 다음 작업" §5~6.

**결정일**: 2026-08-14
**배경**: GPT Image 2가 이미지 입력과 편집을 지원함이 확인됨.

**근거**: "Example > Description" 원칙, 공식 모델 문서 확인.

## D-010: 반복은 평가 진단 이후에만 진행
**결정일**: 2026-08-14
**배경**: 최대 반복 수만큼 후보를 미리 생성하면 앞선 평가가 다음 생성에 반영되지 않아 수렴 루프가 단순 배치 생성으로 퇴행한다.
**결정**: runner는 현재 iteration의 후보만 계획한다. 2회차 이상은 이전 평가의 `next_prompt_adjustment`를 `--diagnosis`로 전달해야 실행할 수 있다.

## D-011: p8-1 텍스트는 후처리
**결정일**: 2026-08-14
**결정**: 시대 전환 이미지는 텍스트 없이 생성하고 `40년 후. 2007.`은 SVG 오버레이로 적용한다. 원본 패널 이미지는 49/49, 오버레이는 18/49로 집계한다.
**근거**: 이미지 모델의 한글 오류로 전체 이미지를 재생성하지 않는다는 Phase 4/5 분리 원칙.

## D-012: 파일럿 리뷰 복사본만 Git 추적
**결정일**: 2026-08-15
**배경**: Git 미추적 후보는 GitHub Pages의 사람 블라인드 검토 화면에서 조회할 수 없다.
**결정**: 생성 원본과 일반 탈락 후보는 계속 `.candidates/`에 두되, 명시적 파일럿 리뷰 세트는 1MB 이하 WebP 복사본만 `panels/convergence/{review-set}/assets/`에 커밋한다.
**근거**: 6개 리뷰 복사본 합계가 약 1.1MB로 저장소 부담이 작고, 공개 수렴 UI에 필요한 최소 자산이다.

## D-013: 사람 선택이 선호 메모리의 유일한 패널 승격 경로
**결정일**: 2026-08-15
**결정**: AI Evaluator는 추천만 기록한다. CLE3 `수렴` 탭에서 사람이 후보를 선택하고 근거를 GitHub에 반영했을 때만 `approved_panel` 앵커를 만든다. 다음 생성은 캐릭터 시트와 관련 승인 패널을 함께 참조한다.
**근거**: 평가 모델의 자기강화로 preference memory가 오염되는 것을 막고 Always Stay In The Loop 원칙을 유지한다.
